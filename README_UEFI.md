# Campfire Hunt: частичный перенос под UEFI / EDK II

Это настоящее X64 UEFI-приложение с игровой логикой из оригинального
`CampfireHunt.c`, а не переименованный HelloWorld или Windows EXE. Цель работы —
компиляция и линковка игры под UEFI. Полноценный игровой интерфейс пока отсутствует.
`UefiMain` инициализирует карту и состояние игры, выполняет диагностическую
симуляцию с исходными правилами при 60 кадрах/с и выводит результаты в консоль.
Запуск этого EFI в прошивке или QEMU в рамках проверки **не выполнялся**.

Оригинальные `CampfireHunt.c`, `include/`, `lib/`, `images/`, `audio/`, README,
таблицы рекордов и стиль Raygui сохранены без изменений.

## Что перенесено

Исходник для сравнения: корневой `CampfireHunt.c`, Git revision
`cb41f9c3a2c2a2cd3a5f06fa404b998787e59b6a`.

Часы и состояние клавиш передаются ядру параметрами. Генератор случайных чисел
реализует MSVC `rand` с явным состоянием (начальное зерно 1); диапазоны и формулы
оригинала сохранены. Карта использовала также Raylib `GetRandomValue`: её
распределение сохранено, конкретная случайная последовательность может отличаться.
Удалены только платформенные аргументы текстур, звука и камер. Переносимое ядро
не включает заголовки UEFI, Raylib или Windows и не использует hosted C runtime.

### Обоснованные отличия и исправления только в UEFI-ядре

- Новые враги полностью обнуляются: оригинал оставлял `lastAttack` и кадр смерти
  неинициализированными, поэтому их исходное поведение не было определено.
- Массив гоблинов имеет фиксированную ёмкость 8. Исходный `realloc` менял лишь
  локальную копию указателя и мог оставлять вызывающему коду освобождённый адрес.
  Ограничения появления врагов остались 5/8.
- Удаление монет обрабатывает каждый элемент один раз. Оригинал мог уменьшить
  количество до −1 при сборе последней истёкшей монеты и пропускал сдвинутые элементы.
- Счётчики появления насыщаются на `INT_MAX`, предотвращая signed overflow;
  обычные интервалы не менялись.
- Явные преобразования небольших целых координат в `float` устраняют C4244 с `/WX`.

Сохранены и особенности оригинального порядка обновления: монеты обрабатываются
после проверки паузы/окончания игры, а в парном режиме их срок уменьшается при
обработке каждого игрока. `lastAttack` игрока меняется при попадании, а не при
любом нажатии. Это не переосмысленная реализация механик.

## Что не перенесено

Raylib/Raygui, OpenGL, окна, отрисовка, камеры, меню и выбор персонажа, загрузка
текстур, звук, физическая клавиатура/мышь и файловое сохранение рекордов.
Они требуют отдельных UEFI-реализаций (например, GOP и Simple Text Input).
Windows-библиотеки `opengl32`, `gdi32`, `winmm` и DLL в EFI не линкуются.
В ядре есть правила парного режима, но нет интерфейса для двух игроков в UEFI.

в EDK II не нужно. `Conf` создаётся из шаблонов внешнего EDK II.

## Требуемые инструменты

- Windows 11; Python 3.11 (проверено 3.11.9).
- Visual Studio 2022 Build Tools: C++ x86/x64, Windows SDK (проверен MSVC 14.44.35207).
- NASM (в PATH или стандартном `Program Files/NASM`).
- Git и внешняя подготовленная копия TianoCore EDK II с submodules.

QEMU, OVMF, IASL и WinGet для этой компиляции не требуются. Существующие работающие
инструменты переустанавливать не нужно. Пути корня игры и EDK II должны быть без
пробелов и специальных символов cmd. Пробелы в пути Visual Studio поддерживаются:
скрипт обнаруживает VS через `vswhere`, затем вызывает корректный `.cmd`-launcher.

### Важное уточнение версии EDK II

В исходном стартере записан `edk2-stable202608`, но фактический локальный checkout
оказался `37b18eca7958215fcf81b297e313adf60c0a70cb`
(`edk2-stable202608-593-g37b18eca79`). Все приведённые результаты получены на этом
коммите. Сборка именно на чистом теге `edk2-stable202608` отдельно не проверялась.
Для точного повторения используйте указанный проверенный коммит. Исходники EDK II
в ходе переноса не патчились; обнаруженные изменения режимов файлов сохранены.

### Подготовка внешнего EDK II

Если checkout уже есть, используйте его. Для нового окружения можно вне каталога
игры скачать EDK II на проверенной ревизии. Например, в отдельной папке инструментов:

```powershell
git clone https://github.com/tianocore/edk2.git edk2
git -C edk2 switch --detach 37b18eca7958215fcf81b297e313adf60c0a70cb
git -C edk2 submodule update --init --recursive
```

Эти команды нужны только для подготовки нового внешнего checkout преподавателем.
Build-скрипты сами не скачивают EDK II, не переключают его ревизию и не обновляют
существующие submodules.

Из корня **Campfire-Hunt** задайте фактическое местоположение:

```powershell
$env:EDK2_DIR = 'C:\tools\edk2'
python scripts/edk2.py doctor
python scripts/edk2.py bootstrap
```

В текущем локальном окружении допустим относительный путь:

```powershell
$env:EDK2_DIR = (Resolve-Path '..\edk2-vscode-starter\third_party\edk2').Path
```

Также у `doctor`, `bootstrap` и `build` есть `--edk2 PATH`, имеющий приоритет над
переменной окружения. Если оба не заданы, проверяется соседняя папка стартера.

### Исправление BaseTools

Windows makefiles EDK II выбирают `HOST_ARCH=IA32`, заголовки Ia32 и Win32-инструменты.
Старое сочетание этих заголовков с `vcvars64.bat` давало C4311/C4312 в `BasePeCoff.c`.
Скрипт использует `vcvars32.bat` и явно задаёт `HOST_ARCH=IA32`. Для самой игры
`build -a X64 -t VS2022` выбирает X64-компилятор из `tools_def` независимо от этого.
Сохранены `/WX` и штатные предупреждения. После `edksetup.bat VS2022` отдельно
запускается `nmake c`, и проверяется его реальный exit code: внутренний batch EDK II
может терять статус ошибки после `popd`. Проверяется наличие результатов BaseTools.
Для неявно генерируемых MSVC memory intrinsics подключена штатная
`MdePkg/Library/CompilerIntrinsicsLib`, без подмены C runtime Windows-библиотеками.

## Сборка и проверка

После успешного bootstrap, из корня игрового репозитория:

```powershell
python scripts/edk2.py build --target DEBUG
python scripts/edk2.py build --target RELEASE
python scripts/edk2.py verify --target DEBUG
python scripts/edk2.py verify --target RELEASE
python scripts/edk2.py test
```

Альтернативная PowerShell-команда (выполняет реальный EDK II):

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build-uefi.ps1 -Target DEBUG -Edk2 $env:EDK2_DIR -Bootstrap
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build-uefi.ps1 -Target RELEASE -Edk2 $env:EDK2_DIR
```

Собирайте конфигурации последовательно: EDK II использует общий `Conf`.
При повторной сборке скрипт выполняет штатный `build ... -m ... clean` только для
сгенерированной сборки этой конфигурации и её библиотек. Старый конечный EFI
удаляется, затем обязательны успешные компиляция/линковка и свежий результат.
Это исключает ложный успех от кэша EDK II или старого файла.
При первой сборке очистка пропускается, поскольку Makefile ещё не созданы.

Артефакты:

```text
Build/CampfireHunt/DEBUG_VS2022/X64/CampfireHunt.efi
Build/CampfireHunt/RELEASE_VS2022/X64/CampfireHunt.efi
```

После сборки печатаются размер, SHA-256 и PE-заголовки. Проверяются реальные
`MZ`/`PE` сигнатуры, PE32+, Machine=0x8664, Subsystem=10, ненулевая точка входа,
границы секций и отсутствие таблицы импорта DLL. Скрипт также проверяет
`GameCore.c` в Makefile, `GameCore.obj` в OUTPUT и модульной `.lib`, а в `.map` —
связанные игровые функции `GenerateGoblinPosition`, `GenerateMonMonPosition`,
`UpdateObjects`, `InitWorld`, `UpdateGame`, `UpdateDeathAnimations`.
Часть других функций оптимизатор встраивает в вызывающие функции.

Рядом с EFI сохраняется `verification.json` с конфигурацией, коммитом EDK II,
SHA-256 результата и исходников; отчёты EDK II — `Build/DEBUG-report.txt` и
`Build/RELEASE-report.txt`. Каталоги OUTPUT/DEBUG внутри модуля содержат объектные
файлы, библиотеку и карту линковки. Python завершается ненулевым кодом при ошибке.
Отсутствие RELEASE PDB при штатном копировании EDK II допустимо: PDB в RELEASE
не создаётся и не является требуемым результатом компиляции.

экспорта получено 13 824 байта вместо 13 312 в основном каталоге.

Тесты проверяют начальное состояние, PRNG, генерацию и параметры врагов/объектов,
урон и строгие интервалы атак, здоровье/жизни, награды, сбор/истечение монет,
лечение, этапы на граничных значениях, очки, движение/границы/паузу, парный режим,
лимиты/переполнение счётчиков, смерть врагов и распределение карты. Эталоны
извлекаются заново из оригинальных функций `tests/extract_reference.py`; это
не тестирование через заглушку UEFI. Звуковые вызовы удаляются только из эталонов
host-тестов; арифметика и условия оригинала остаются. Известные исходные дефекты
проверяются отдельными ожидаемыми результатами после исправления.

Дополнительная проверка валидатора после сборки обеих конфигураций:

```powershell
python tests/verify_pe_test.py
```

Она читает реальные EFI и проверяет отказ на копиях с неправильными machine,
subsystem, magic, точкой входа, импортом DLL, PE-сигнатурой, смещением заголовка,
а также на пустом, текстовом и обрезанном файле. Дополнительно заголовки обоих
готовых EFI проверены установленным MSVC `dumpbin /headers`.

### Проверка Windows-сборки

Имеющийся MinGW GCC 6.3 (`mingw32`) не подходит к приложенной X64-библиотеке:
команда из исходного README заканчивается undefined references. Зависимости не
переустанавливались. Успешно проверен альтернативный путь с уже установленным MSVC:

```powershell
python scripts/build-windows-msvc.py
```

Скрипт получает экспорты существующей `lib/raylib.dll`, создаёт локальную MSVC
import library через `lib /def`, собирает **корневой исходник** и помещает EXE и DLL
в `Build/windows-compat`. Для поиска ресурсов запускать из корня репозитория:

```powershell
.\Build\windows-compat\CampfireHunt.exe
```

### Локальный стартер (не нужен при сдаче)

В `edk2-vscode-starter` сохранён HelloWorld и добавлен однозначный выбор приложения:

```powershell
python scripts/edk2.py bootstrap
python scripts/edk2.py build --target DEBUG
python scripts/edk2.py build --target RELEASE
python scripts/edk2.py build --app HelloWorld --target DEBUG
```

По умолчанию собирается Campfire Hunt из соседнего игрового репозитория; другой
путь можно задать `CAMPFIRE_HUNT_DIR`. Выбор приложения и конфигурации используется
также при поиске EFI и подготовке QEMU. Нет fallback к HelloWorld или другой
конфигурации. Сами игровые исходники и конфигурация пакета в стартер не копируются.

## Что сдавать

На Gitos отправляется содержимое **Campfire-Hunt**: исходная игра и ресурсы,
`CampfireHuntPkg/`, `scripts/`, `tests/`, `.vscode/tasks.json`, `.gitignore` и этот
README. `third_party/edk2`, `Build`, `Conf`, `.qemu`, Python caches и локальные
логи не нужны и исключены из Git. EFI остаются локальными артефактами; преподаватель
может получить их указанными командами. Соседний стартер и многогигабайтный архив
EDK II отправлять не нужно.

В процессе подготовки `git add`, `commit`, `push` и изменения remote/истории
не выполнялись. Отправка в университетский Git остаётся за владельцем проекта.

## Ограничения

Это перенос вычислительной части игры с диагностическим UEFI entry point.
Компиляция и формат EFI подтверждены; исполнение UEFI, графика, звук, управление
и постоянное хранение рекордов ещё требуют отдельной работы. Build helper
ориентирован на Windows/VS2022/X64; другие toolchain/архитектуры не проверялись.
Именно чистый тег `edk2-stable202608` не проверен — проверен указанный более поздний
коммит. Различия с оригиналом и обнаруженные ошибки перечислены выше.
